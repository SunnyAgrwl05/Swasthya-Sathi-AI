# Swasthya Sathi AI

Swasthya Sathi AI is an AI-powered attendance and workforce monitoring system for rural healthcare teams. It combines a FastAPI backend, a React dashboard, and an AI operations agent that can understand supervisor requests, manage attendance records, summarize trends, and generate operational updates.

The project is designed around a practical public-health workflow: supervisors can track ASHA, ANM, and Anganwadi worker attendance, identify low-attendance patterns, and ask natural-language questions in Hindi or English without navigating every dashboard action manually.

## Problem Statement

Rural health centres often rely on paper registers, spreadsheets, and messaging groups to manage field-worker attendance. These workflows make it difficult to:

- View attendance status in real time.
- Detect workers who have not marked attendance.
- Compare recent attendance performance across workers.
- Generate supervisor-ready summaries quickly.
- Follow up on low-attendance cases before they affect service delivery.

Swasthya Sathi AI turns these fragmented workflows into a connected dashboard and AI-assisted reporting system.

## Key Features

- Natural-language AI operations agent for attendance workflows.
- Hindi and English interaction support.
- Health worker registration and listing.
- Attendance creation and update APIs.
- Attendance analytics with percentage summaries.
- Low-attendance worker detection.
- Daily broadcast generation for supervisor follow-up.
- Weekly insight reports.
- React dashboard with cards, charts, worker table, and chat panel.
- SQLite persistence through SQLAlchemy.
- FastAPI REST API with autogenerated OpenAPI docs.
- Backend and frontend tests.
- Docker and Render/Vercel deployment support.

## AI Workflow

The AI agent is not limited to plain text generation. It receives structured attendance-related capabilities and can call the appropriate workflow when a supervisor asks for an action or report.

Example prompt:

```text
Sunny Kumar ko present mark karo aur uska monthly summary dikhao
```

The backend can resolve the worker, update attendance, and return a formatted operational response. The same agent layer can also generate daily broadcasts, identify missing attendance, and summarize low-attendance workers.

For methodology details, see [docs/methodology.md](docs/methodology.md).

## API Overview

| Method | Endpoint | Description |
| --- | --- | --- |
| GET | `/` | Backend health check |
| GET | `/api/workers` | List registered health workers |
| POST | `/api/workers` | Create a health worker |
| DELETE | `/api/workers/{worker_id}` | Delete a health worker |
| GET | `/api/attendance` | List attendance records |
| POST | `/api/attendance` | Create or update attendance |
| GET | `/api/analytics/summary` | Get attendance analytics |
| POST | `/api/chat` | Send a message to the AI operations agent |
| GET | `/api/broadcast/daily` | Generate a daily broadcast |
| GET | `/api/insights/weekly` | Generate weekly insights |
| POST | `/api/insights/weekly` | Generate weekly insights with language selection |

## Local Setup

Detailed setup instructions are available in [docs/setup.md](docs/setup.md).

### Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python seed.py
uvicorn main:app --reload
```

On Windows PowerShell:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python seed.py
uvicorn main:app --reload
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Open the frontend at:

```text
http://localhost:5173
```

If the API runs on a separate host, set `VITE_API_URL` for the frontend.

## Environment Variables

The backend can run for basic API and test workflows without an AI key, but AI chat and generated reports require at least one model provider key.

| Variable | Purpose |
| --- | --- |
| `GEMINI_API_KEY` | Primary Google Generative AI key |
| `GEMINI_API_KEY_2` to `GEMINI_API_KEY_5` | Optional fallback Gemini keys |
| `GEMINI_MODEL` | Optional model override, defaults to `gemini-2.5-flash` |
| `OPENROUTER_API_KEY` | Optional fallback provider for some report flows |
| `VITE_API_URL` | Frontend API base URL |
